Implementation choices and limits:

- The recommended warning option for sensitive paths is `WARN SENSITIVE`, preserving
  successful collection while making the review requirement explicit. Warnings do
  not prove a delivery safe. Disabling rename detection exposes deleted authority
  paths even when their contents move to an ordinary filename. Finding 21 calls for
  per-task base..head diffs; finding 06 and the existing safety check also require
  examining authority changes after head (including status commits). Both ranges
  are scanned, including on repeat collection, and raw diffs are cached per pair.
- Forced verification during running/queued work is recorded but ignored in replay,
  preserving an audit trail without allowing an approval of unfinished delivery.
  All assign/finish/verify/merge/close force paths store `force: true` when used.
- A manual finish clears stored report/head/tests as well as approvals. This is the
  documented reconciliation route; no persistent ignored-branch list is necessary.
  Local cancellation never stops the remote session.
- External queries take a locked snapshot, release the lock, then acquire it briefly
  to compare ledger metadata and append. A concurrent change requires retry rather
  than silently applying a stale result. Ordinary assign/finish/verify transactions
  retain the transaction lock. Unlocked fetches resolve unique temporary Git refs
  and delete them afterward, avoiding shared FETCH_HEAD races even with unusual
  origin ref mappings. The hook remains a read-only, unlocked path.
- Portable replacement of a nonempty directory uses two atomic os.replace renames,
  not an atomic exchange of directory names. Guarded hooks tolerate the short gap;
  publication failure restores the previous payload. Process/power loss between
  renames is not an atomic-directory-exchange guarantee.
- O_NOFOLLOW protects the final file where the OS provides it; parent-component
  symlink checks do not claim to sandbox a malicious process racing directory
  replacement. Windows lacks the POSIX O_NOFOLLOW guarantee.
- A done report is a provenance claim, not proof of correct work. Review all commits
  and warnings, including rejected siblings. The merge guard follows the recommended
  ancestry rule; cherry-picking changes the head and requires verification of the
  resulting commit (`verify --head <sha>`) before recording integration.
- Review diffs include new text files after add -N. Binary and ignored inputs need
  explicit inspection and a bounded authorized manifest; no claim of automatic
  semantic completeness is made.
