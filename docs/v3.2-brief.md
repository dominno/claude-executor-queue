## N9 (creator request 2026-11-13): load/disk/concurrency guard before launching executors
xq never launches executors, so add a preflight the lead must run right before each launch:
- `xq.py preflight --executor codex|agy` exits non-zero with a clear reason when:
  - 1-minute load average / CPU count > `max_load_per_cpu` (default 1.0);
  - free space < `min_free_gb` (default 5) on the repo volume OR on the temp directory volume (tempfile.gettempdir());
  - running executors of that kind ≥ limit (`limits`: default codex 2, agy 1), counted as max(ledger running tasks,
    live OS processes matched conservatively; document the matching and make it injectable for tests).
- Config in `.agents/config.json`: `{"limits":{"codex":2,"agy":1},"min_free_gb":5,"max_load_per_cpu":1.0}`; validated.
- The Stop hook must NOT demand work for an idle executor while preflight would refuse; it prints the reason instead
  (still read-only, unlocked). `doctor` prints load, free space (both volumes) and running counts.
- Windows: load average unavailable → skip that check with a printed note; disk and count checks still apply.
- SKILL.md: make `preflight` a mandatory step immediately before every Codex launch and agy queue run/delegate.
- Tests with injected readings for each threshold, the hook behaviour, config validation and Windows fallback.
