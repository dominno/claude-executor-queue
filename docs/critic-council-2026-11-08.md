# Critic Council Report: executor-queue skill

## Summary

The council reviewed the skill through five lenses: first-use, correctness, cloud, security, portability and ops. Lenses filed 31 findings, and each one went to a separate verifier. After duplicates were merged, **25 confirmed findings** remain: **0 blockers, 16 important, 9 nice**. One finding was refuted. The verifiers lowered every severity that critics had marked as a blocker.

The most serious gaps are these:

- **Verification state does not hold.** A verdict stays attached after a later `finish`. `--by` can name the task's own executor. `merge` accepts any commit that exists, with no link to the head that was reviewed. Together these weaken the skill's main promise that the maker never checks its own work.
- **Cloud collection breaks in normal use.** Foreign or stale `claude/*` branches block `--discover` for every batch. A report on a branch other than the bound one is dropped without a message. The only reconcile route the docs describe (`--force`) does not exist.
- **Ops friction makes the Stop hook unsafe.** If the installed `xq.py` is missing, the hook blocks every stop. Healthy long jobs are flagged stale and nothing can clear them. `status --open` keeps every task that did not pass, forever.
- **Native Windows is unvalidated, and several failures are concrete.** The lock throws an OSError after about 10 s. The envelope crashes on a cp1252 pipe after it has already written the assign rows. The agy-bridge script cannot be launched. `install.ps1` stops on the Microsoft Store python alias.

## Refuted or unconfirmed

- **The /goal envelope embeds unquoted shell commands built from brief paths and branch names**: refuted. Every field comes from the lead, or from the lead's own git-ignored ledger on `--reprint`. No executor or remote input reaches them, so no trust boundary is crossed. It is a hygiene nit at most.
- Parts of confirmed findings that the verifiers rejected:
  - A plain deletion of CLAUDE.md *is* listed by the SENSITIVE check. Only renames and the paths it does not match are missed.
  - The Windows lock issue does not affect the Stop hook path, because `cmd_hook` takes no lock.
- Severities lowered by the verifiers:
  - Stale verdict, bound-branch drop and the cloud-envelope encoding crash: blocker → important.
  - Hook with a missing `xq.py`: blocker → important.
  - First-use self-verify: important → nice. Merged into the important maker≠checker row.
  - Ops "no terminal state": nice. Merged into the important `status --open` row.
  - Doctor/init order, ledger ignore, symlink, unbound branch, pinned base, head==base, case collision and queued agy: important → nice.

## Nice-to-have (unverified suggestions)

- **Base-branch discovery in a fresh project**: doctor prints the current branch as the "default branch". Strip `origin/`, label the fallback, and require `--main` when origin/HEAD is unset.
- **Codex fix loop with `task --resume-last`**: it fails in a later Claude session. Document that it works only in the same session; otherwise launch the -fix1 brief fresh in the same worktree.
- **A single `delegate` review**: a failure leaves the agy task running with no signal, and a success makes poll exit 1 every run. Document finishing it by hand with the exit code and an absolute `--out`, or add `agy-sync --delegate-exit`.
- **Non-UTF-8 bytes in `--summary`, `--note` or `--evidence`**: they crash with a traceback. Clean the text with surrogateescape→replace before building the event.
- **`assign --executor cloud [--queued]`**: it creates a task that can never be enveloped or collected, yet the hook keeps demanding it. Reject it and point to cloud-envelope, or let cloud-envelope promote it.
- **Untrusted cloud report stored in the ledger without size limits** (security and ops, merged): cap the file size (about 64 KB), summary and test fields, and the number of tests. Drop unknown keys. Store a `report_sha256` for the CHANGED comparison.
- **The primary-checkout recipe needs git 2.31+ (`--path-format`)**: document the requirement and check it in doctor, or use `cd "$(git rev-parse --git-common-dir)/.." && pwd`.
- **The Windows Stop-hook example uses cmd.exe `%USERPROFILE%`**: Claude Code on Windows runs hooks through Git Bash. Use one form that works in both shells, such as `py -3 "$HOME/..."`, and make README, SKILL and the example agree.
