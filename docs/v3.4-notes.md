# v3.4.0

The installable skill lives in `skills/executor-queue/`. Skills CLI and the
offline installers ship `SKILL.md`, `scripts/xq.py` and `LICENSE`.
The skill uses Claude Code's `disable-model-invocation` frontmatter extension.

## Changes to existing workflows

- Cloud result pushes require the exact authorized push URL and session branch.
  New envelopes group tasks independently, including envelopes based on the
  same brief. The ledger keeps the report fingerprint and uses the full delivery SHA for integration checks.
- Multi-task writes use one JSONL record, so a torn write cannot apply half of
  an envelope. Upgrade every helper sharing the ledger to 3.4 or later and back
  up the ledger before downgrading. Older helpers skip the new records.
- Use explicit reconciliation for a terminal result on a closed task or for
  re-verifying integrated work. The ledger retains the historical records. Poll
  releases a closed task's slot when it can confirm a terminal result.
- For a local Skills CLI source, pull the repository and repeat the original
  `npx skills add` command in the same scope. The offline installer also honors
  the selected `CLAUDE_CONFIG_DIR` when `CLAUDE_SKILLS_DIR` is unset.

## Publication checklist

1. Run the Python suites and the Skills CLI smoke test with a clean profile.
2. Review Git history, release artifacts, and GitHub Actions history and logs for
   private metadata or sensitive content before changing repository visibility.
3. Once the repository is public, install from a clean project without Git
   credentials using `npx skills add dominno/claude-executor-queue --skill executor-queue -a claude-code`.
   Start a Claude Code session, invoke `/executor-queue`, and verify the installed helper path.
