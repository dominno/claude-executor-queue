# v3.5.0

## Upgrading

- Commit and review Codex work before verifying the delivery. Use the original
  worktree and name the reviewed commit when reconciling a result that arrived
  with local changes. See [Codex verification](codex.md#tasks).
- Older successful Codex entries without a recorded delivery SHA need explicit
  reconciliation. After independently reviewing the committed result, use
  `xq finish --id <id> --status done --force --head <reviewed-sha>` and verify it again.
- Keep one open installer per destination, including older offline installers.
  See [offline installation](installation.md#offline-installation) when moving a copy to
  `CLAUDE_CONFIG_DIR`. Use xq 3.4 or newer across sessions sharing a ledger with batch records.
- `xq doctor --offline` checks local prerequisites and skips executor authentication.
  Review the [cloud push scope](cloud.md) before authorizing any result transfer.

## Publication checklist

1. Run the Python suites, including native Windows checks, and the Skills CLI smoke test.
2. Review Git history, release artifacts, and GitHub Actions history and logs for
   private metadata and sensitive content before changing repository visibility.
3. Once public, install without Git credentials using
   `npx skills add dominno/claude-executor-queue --skill executor-queue -a claude-code`.
   Invoke `/executor-queue` in a new Claude Code session and confirm the helper path.
